# Design: xiaomi-wifi-provisioning

## Context

小咪当前的联网路径：`main.cpp` 唤醒时调 `wifiEnsureUp()`（`src/stackchan/wifi_stream.cpp`，
与 buddy 固件共用），后者用编译期宏 `STACKCHAN_WIFI_SSID/PASS` 调 `WiFi.begin()`，
6 秒预算连不上就放弃。凭据在固件里 → 换网必须重烧。

已有可复用的基建：
- 控制面板的 `WebServer` + 独立 HTTP 任务（openspec change `xiaomi-control-panel`）——
  配网页可以直接复用这套，成本大降。
- `settings.cpp` 的 NVS 存取模式（Preferences，命名空间 `stackbuddy`）。

## Goals / Non-Goals

**Goals:**
- 存多组网络，到了哪儿自动连哪儿——带着上下班不用接电脑。
- 在已联网时通过面板增删网络（出门前先把目的地网络加好）。
- 到陌生地方无已知网络时，靠设备自身 + 一部手机完成配网。
- 现有设备升级后行为不变（编译期凭据自动迁移进 NVS）。

**Non-Goals:**
- 企业级 WPA2-Enterprise（802.1X）网络——需要证书与身份，另议。
- Captive portal 网络的自动"同意条款"（小咪没浏览器，无解，只做明确报错）。
- 扫二维码配网（层 3b）——本次不做，留作后续。
- 云端配网 / 手机 App。

## Decisions

1. **凭据存 NVS，键为 `wn0..wn4`**（5 组，JSON 或 `ssid\0pass` 打包）。5 组够覆盖
   家/公司/常去的两三个地方，且不至于让 WiFiMulti 扫描连接拖太久。
2. **连接用 `WiFiMulti`**（arduino-esp32 自带）：把所有已存网络 `addAP()`，`run()`
   会扫描现场并连信号最强的已知网络。相比手写"逐个试"，它天然处理"两个已知网络同时
   在场选哪个"。
3. **编译期凭据 = 出厂种子，只灌一次**：首次启动发现 NVS 凭据表为空且编译期 flag
   不是占位符 → 写入槽位 0，并置一个 `wseed` 标记防止重复灌（用户手动删掉后不该被复活）。
   保证已在用的设备升级固件后照常联网。
4. **连接预算放宽到 15s**（原 6s）：WiFiMulti 要先扫描（~2-3s）再关联。仍有上限，
   避免唤醒后长时间卡住。
5. **配网模式（SoftAP + 强制门户）触发条件**：唤醒时连接失败**且**已存网络列表非空或
   为空都进入——即"连不上就配网"，而不是只在列表为空时。理由：用户到新地方最常见的
   情形就是"存了几个网但都不在场"。
6. **强制门户实现**：`WiFi.softAP("小咪-setup", <密码>)` + `DNSServer` 把所有域名解析
   到 AP 自身 IP → 手机连上后系统自动弹出配网页。
   **实现落点（实施中修正）**：AP 模式与配网页并入 `web_panel.cpp`，而不是原计划的
   独立 `wifi_setup_ap.{h,cpp}`。理由：两个 `WebServer` 实例会抢 80 端口，而面板与
   配网模式本就互斥（连上了才有面板，连不上才配网）——共用一个 server 实例 + 一个
   HTTP 任务（同一个循环里顺带 pump DNS）最简单也最不容易出错。
7. **配网热点带密码，显示在屏幕上**。开放热点会让路人连上改配置；密码固定
   （`xiaomi-setup` 之类）并显示在小咪屏幕上，物理在场即可见，符合"配网本就是物理在场
   才做的事"。
8. **配网模式超时 10 分钟**（可调），无人配置则关热点回打盹——不长期广播、不白耗电。
9. **密码只写不读**：面板 `GET /api/networks` 只返回 SSID 列表与当前连接项，
   永不返回密码字段；配网页同理。改密码 = 重新提交该 SSID。
10. **面板扫描辅助**：`GET /api/networks/scan` 返回附近网络（SSID/信号/加密与否），
    让用户点选而不是手打 SSID。扫描是阻塞操作（~2s），放 HTTP 任务里做，
    主循环不受影响（沿用面板的任务隔离）。
11. **配网成功后不重启**，直接尝试用新凭据连接并回到正常流程——重启会打断用户体验，
    而且我们本来就没有"重启才能应用"的技术约束。

## Risks / Trade-offs

- [WiFiMulti 扫描期阻塞] 扫描在主循环里做会卡住触摸/画面。→ 连接流程本就发生在
  唤醒瞬间（用户已在等待，屏幕显示"找网络中…"），可接受；但 MUST NOT 放进
  对话进行中的路径。
- [SoftAP 与 STA 共存的内存/射频压力] → 进配网模式时先 `WiFi.disconnect()` 停 STA，
  纯 AP 模式跑门户，配好再切回；不做 APSTA 并存。
- [强制门户在不同手机上弹出行为不一致]（iOS/Android/Win 探测 URL 各不同）→
  门户对所有未知路径一律 302 到配网页；即使系统没自动弹，用户手动打开任意网址也会跳转。
- [访客网络客户端隔离] 会让面板打不开（本变更不能解决，属网络策略）→ 屏幕在连上后
  仍显示面板地址，用户自行判断；文档写明这一情形。
- [NVS 明文存密码] → 已在 proposal 安全边界声明。ESP32 NVS 加密需要 eFuse 烧录
  flash encryption，代价与收益不匹配（桌宠不是保险箱）。
- [5 组上限] 满了怎么办 → 面板提示需先删一个再加；不做 LRU 自动淘汰（静默丢掉用户
  存过的网络比报错更糟）。

## Resolved

- **配网热点密码**：`zhumi-setup`（用户 2026-07-19 拍板），显示在设备屏幕上。
- **实施顺序**：本变更与 `xiaomi-control-panel` 一并真机验收（用户选择），
  因此面板的验收任务与本变更的验收合并进行。
